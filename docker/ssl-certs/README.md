# SSL Certificate Management

This directory contains the infrastructure for managing SSL certificates using Let's Encrypt with Nginx and Certbot.

## Overview

- **Nginx ACME Challenge**: Temporary nginx service that handles Let's Encrypt ACME challenges
- **Certbot**: Let's Encrypt client for obtaining and renewing certificates
- **Automatic Renewal**: Certificates are automatically renewed and deployed to APISIX

## Quick Start

### 1. Obtain Certificates (First Time)

```bash
cd docker/ssl-certs
./scripts/obtain-certs.sh
```

For staging/testing:
```bash
./scripts/obtain-certs.sh --staging
```

### 2. Renew Certificates

```bash
cd docker/ssl-certs
./scripts/renew-certs.sh --deploy-hook
```

The `--deploy-hook` flag automatically:
- Copies certificates to APISIX
- Reloads APISIX configuration

### 3. Setup Certificates for APISIX

```bash
cd docker/apisix
./scripts/setup-letsencrypt-certs.sh
```

This script:
- Copies Let's Encrypt certificates to APISIX certs directory
- Copies certificates to APISIX container
- Restarts APISIX if needed

## Certificate Locations

### Let's Encrypt Storage
- **Live Certificates**: `data/certbot/conf/live/thaliumx.com/`
  - `fullchain.pem` - Certificate + chain
  - `privkey.pem` - Private key
  - `cert.pem` - Certificate only
  - `chain.pem` - Chain only

### APISIX Usage
- **APISIX Certificates**: `docker/apisix/certs/letsencrypt/`
  - `server.crt` - Full chain (for APISIX)
  - `server.key` - Private key (for APISIX)

### Container Paths
- **APISIX Container**: `/tmp/certs/`
  - `server.crt` - Certificate
  - `server.key` - Private key

## Automatic Renewal

### Cron Job Setup

Add to crontab for automatic renewal:

```bash
# Renew certificates daily at 2 AM
0 2 * * * cd /home/ubuntu/thaliumx-v1/docker/ssl-certs && ./scripts/renew-certs.sh --deploy-hook >> /var/log/letsencrypt-renewal.log 2>&1
```

### Manual Renewal

```bash
cd docker/ssl-certs
./scripts/renew-certs.sh --deploy-hook
```

For localhost development, self-signed certificates are automatically generated by `setup-letsencrypt-certs.sh` when Let's Encrypt certificates are not available.

## Troubleshooting

### Certificates Not Found

If certificates don't exist:
1. Ensure domains point to your server
2. Ensure port 80 is accessible for ACME challenges
3. Run `./scripts/obtain-certs.sh --staging` first to test

### APISIX Not Using Certificates

1. Check certificates are in `docker/apisix/certs/letsencrypt/`
2. Verify APISIX container has certificates mounted
3. Check APISIX config points to `/tmp/certs/server.crt` and `/tmp/certs/server.key`
4. Restart APISIX: `docker restart thaliumx-apisix`

### Certificate Renewal Fails

1. Check nginx-acme service is running: `docker ps | grep nginx-acme`
2. Verify port 80 is accessible
3. Check logs: `docker compose logs certbot`
4. Try staging first: `./scripts/obtain-certs.sh --staging --force-renewal`

## Production Notes

1. **Use Production Certificates**: Remove `--staging` flag for production
2. **Set Up Automatic Renewal**: Configure cron job for certificate renewal
3. **Monitor Expiry**: Let's Encrypt certificates expire after 90 days
4. **Backup Certificates**: Keep backups of certificate files
5. **Update Email**: Update email in `obtain-certs.sh` for certificate notifications

## Integration with APISIX

APISIX is configured to:
- Read certificates from `/tmp/certs/server.crt` and `/tmp/certs/server.key`
- Automatically reload when certificates are updated
- Support SNI (Server Name Indication) for multiple domains

The renewal script automatically:
1. Renews certificates via Certbot
2. Copies certificates to APISIX directory
3. Copies certificates to APISIX container
4. Restarts APISIX to load new certificates
